# tsppc ping (relay-only) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `tsppc ping <name|IP>` works like `tailscale ping` over DERP relays, and tsppc answers disco pings from other nodes, so `tailscale ping <mac>` gets pongs.

**Architecture:** A sans-I/O disco module (`src/disco/`) builds, seals, opens and parses disco messages. The data plane stops dropping disco packets: it hands them to the disco layer, answers pings with pongs on the region they arrived on, and sends our pings to the peer's home region. The daemon gets a `ping <ip>` IPC request with a deferred reply; the CLI loops one request per ping and prints upstream's lines.

**Tech Stack:** C99 (gnu99), gcc-4.0 with the 10.4u SDK for PowerPC, clang with ASan/UBSan and the in-tree fuzz harness on the host; Go (host only) for test vectors from upstream's own code.

**Spec:** `docs/superpowers/specs/2026-11-10-tailscale-ppc-design.md` ("Commands for the first version" and the `tsppc ping` paragraph; milestone 8).

## Global Constraints

- Build flags as everywhere: `-std=gnu99 -Wall -Wextra -Werror`; gcc-4.0 for `ppc` against the 10.4u SDK (no functions missing from that SDK, e.g. no `memmem`, no `strnlen`); clang on the host. `make test`, `make asan`, `make fuzz` and `tools/vm-test.sh leopard` must pass.
- Every parser of untrusted input (disco packets from relays, the new IPC request) gets unit tests, ASan/UBSan, and a fuzz target `tests/fuzz_<name>.c`.
- Test-only behaviour behind `TS_TEST_HOOKS`; add new hook symbols and environment names to `tools/check-release.sh`.
- Public repo: fixtures use made-up keys, names (`*.example.ts.net`) and 100.64.x.x addresses.
- Upstream reference: tailscale@9476be94035afa8b896d1e07ee352741b35be7fb. Facts in Appendix A.
- X25519 is expensive on a G3: shared keys are precomputed once per (our disco key, peer disco key) and cached; never one X25519 per packet. Opening a packet from a disco key we have no cached key for counts against the existing DH budget (`TS_WG` DH budget, 20 per second) or a disco-specific one of the same size.
- Disco private key: comes from `ts_state.disco_priv`; wiped wherever node private keys are wiped.

## Review Focus

1. A disco packet from a relay whose sender disco key is not a current peer's (netmap `disco_key`), or whose frame source is not a peer: dropped, no pong, no X25519 (budget).
2. A flood of pings from one peer: pongs are rate-limited (at most 10 per second per peer, at most 50 per second total), excess dropped and counted.
3. `tsppc ping` to self, to an unknown name, to an offline peer, to a peer with no disco key, to an expired peer: upstream's message and exit code each time (Appendix A, item 4).
4. The daemon stops (`down`, logout, SIGTERM) while a ping request is pending: the client gets an error reply or EOF, never a hang beyond its timeout, and nothing leaks.
5. A pong that arrives after its ping timed out, or with an unknown TxID, or twice: ignored.

### Task 1: Disco messages, sans I/O

**Files:**
- Create: `src/disco/disco.h`, `src/disco/disco.c`, `tests/test_disco.c`, `tests/fuzz_disco.c`, `tools/disco-vectors/main.go` (+ its `go.mod` pinning tailscale.com at the reference commit), `tests/disco_vectors.inc`
- Modify: `tests/main.c`

**Interfaces (produces):**
- `#define TS_DISCO_MAGIC_LEN 6`, `TS_DISCO_HDR_LEN 38` (magic + sender disco public key), `TS_DISCO_NONCE_LEN 24`, `TS_DISCO_TXID_LEN 12`, `TS_DISCO_PING_LEN 124`, `TS_DISCO_PONG_LEN 110`, `TS_DISCO_MAX 1500` (largest packet built or accepted here).
- `int ts_disco_looks_like(const uint8_t *p, size_t n);` magic prefix and `n >= 6+32+24`.
- `typedef struct { uint8_t k[32]; } ts_disco_shared;` and `void ts_disco_shared_init(ts_disco_shared *s, const uint8_t my_priv[32], const uint8_t their_pub[32]);` (one X25519 + HSalsa20, via `ts_box_beforenm`).
- `int ts_disco_seal_ping(uint8_t *out, size_t cap, const uint8_t my_disco_pub[32], const ts_disco_shared *s, const uint8_t nonce[24], const uint8_t txid[12], const uint8_t my_node_pub[32]);` returns length 124 or -1.
- `int ts_disco_seal_pong(uint8_t *out, size_t cap, const uint8_t my_disco_pub[32], const ts_disco_shared *s, const uint8_t nonce[24], const uint8_t txid[12], const uint8_t src_ip16[16], uint16_t src_port);` returns 110 or -1.
- `typedef struct { int type; uint8_t txid[12]; int have_node_key; uint8_t node_key[32]; uint8_t src_ip16[16]; uint16_t src_port; } ts_disco_msg;` (type 1 ping, 2 pong; other types reported as their byte so the caller can ignore them).
- `int ts_disco_open(ts_disco_msg *m, const uint8_t *p, size_t n, const ts_disco_shared *s);` opens with the box (tag first) and parses: version byte must be 0; extra bytes ignored; ping NodeKey present only if the 32 bytes after the TxID exist and are not all zero (Appendix A, item 2). 0 or -1. `ts_disco_sender(p)` returns a pointer to the 32-byte sender key in the header.
- Wire format and box: Appendix A, items 1 and 2.

### Task 2: Disco in the data plane (answer pings, send pings, take pongs)

**Files:**
- Modify: `src/data/dataplane.{h,c}`, `src/daemon/dataplane_io.{h,c}`, `tests/test_dataplane.c`, `tests/test_dpio.c`, `tools/check-release.sh` if hooks are added.

**Interfaces:**
- Consumes Task 1.
- `ts_dp_start` takes the disco private key as well (`const uint8_t disco_priv[32]`), derives the public key itself, and wipes the private key on stop/free like `node_priv`.
- Peers keep their netmap `disco_key`; a changed disco key drops that peer's cached shared key.
- Incoming relay packet with the disco prefix (today dropped at `dataplane.c` near the `disco` counter):
  - frame source must be a current peer, and the header's sender key must equal that peer's netmap `disco_key` (stricter than upstream, Appendix A item 3; a node's disco key only arrives through the netmap here) → else drop, count.
  - shared key from the per-peer cache; computing a missing one uses the DH budget; over budget → drop, count.
  - ping → pong sealed to the same peer, `Src` = `::ffff:127.3.3.40` and port = the region ID it arrived on, sent on that same region's connection (not the home region). Rate limits from Review Focus 2.
  - pong → matched against outstanding pings by TxID (at most 16 outstanding; each expires after its timeout); first match wins; result delivered through a new callback.
  - other types (CallMeMaybe and the relay types) → ignored, counted.
- `int ts_dp_ping(ts_dp *dp, uint32_t peer_ip, uint32_t timeout_ms, uint64_t cookie, int64_t now_ms);` sends a ping to the peer with that tailnet IP on the peer's home region (dial it if needed, like data); returns 0, or a negative code: unknown peer, peer has no disco key, peer key expired, no home region, too many outstanding.
- Result callback in `ts_dp_io`: `void (*ping_result)(void *user, uint64_t cookie, int status, uint32_t latency_us, int region_id);` with status 0 pong, 1 timeout. `region_id` = the region the ping was sent to (Appendix A item 4: upstream prints the destination region).
- Counters (status/test hooks): `disco_in`, `disco_bad`, `pongs_sent`, `pongs_limited`, `pings_sent`, `pongs_in`.
- `dataplane_io` passes `st.disco_priv` into `ts_dp_start` and forwards `ts_dp_ping` / results for Task 3 (`ts_dpio_ping(...)` with the same arguments, and a registered callback).

### Task 3: `ping` over IPC and `tsppc ping`

**Files:**
- Modify: `src/daemon/ipc.{h,c}`, `src/daemon/ipc_reply.{h,c}`, `src/daemon/main.c`, `src/cli/main.c`, `tests/test_ipc.c`, `tests/test_ipc_reply.c`, the IPC fuzz targets.

**Interfaces:**
- Request line `ping <a.b.c.d> <timeout_ms>\n` (dotted quad only, each part 0..255 with no leading zeros; timeout 100..10000). Parsed by an extended `ts_ipc_parse_request` that also returns the arguments; still at most `TS_IPC_LINE_MAX` bytes. Anything else is the existing "unknown request".
- The daemon keeps the client open with no reply until the result arrives; `TS_IPC_CLIENT_TIMEOUT_MS` (10 s) still bounds it. Reply (ok): `ok`, `ping pong <latency_us> <region_id> <region_code>` or `ping timeout`; or `error <text>` with upstream's texts for the `ts_dp_ping` codes ("unknown peer", "peer's node key has expired", ...) and "not connected" when the data plane is not running. A client that closes early cancels its ping. `down`, logout and shutdown answer every pending ping with an error.
- CLI: `tsppc ping [-c N] [--timeout DUR] [--until-direct=BOOL] <name|IP>` with upstream's defaults (10, 5s, true) and `-c 0` = no limit. Name resolution as upstream (Appendix A item 4): IP literal; else a peer whose full name or first label matches case-insensitively, from the `status` reply; our own IP prints `<ip> is local Tailscale IP` and exits 0. Output and exit codes exactly as Appendix A item 4: `pong from <first label> (<ip>) via DERP(<code>) in <ms>ms`, `ping "<ip>" timed out`, `no reply`, `direct connection not established`; Go's Duration rounding to the millisecond (`0s`, `23ms`, `1.5s`). One IPC connection per ping; 1 s pause after each pong.
- All strings from the daemon are cleaned as other replies are.

## Appendix A: upstream facts

From tailscale@9476be9 (`disco/disco.go`, `wgengine/magicsock/magicsock.go`, `endpoint.go`, `cmd/tailscale/cli/ping.go`, `ipn/ipnlocal/local.go`, `tailcfg/tailcfg.go`). Items marked (recalled) were not in the copies read and must be checked against upstream source before relying on them.

1. **Packet.** `Magic(6) | sender disco public key(32) | nonce(24) | box`. Magic is `54 53 f0 9f 92 ac`. The box is NaCl `crypto_box` (X25519, HSalsa20, XSalsa20-Poly1305, 16-byte tag first) between our disco private key and the peer's disco public key; the nonce is random and sits before the ciphertext (recalled: `types/key/disco.go` `Seal`). Plaintext: `type(1) | version(1)=0 | payload`, trailing bytes ignored. Types: 1 ping, 2 pong, 3 CallMeMaybe, 4–9 relay messages. Over DERP disco and WireGuard both arrive as RecvPacket frames; disco is recognised only by the magic prefix (WireGuard packets start 0x01–0x04).
2. **Ping** payload: `TxID(12) | NodeKey(32, the sender's WireGuard node public key) | zero padding`. Parse: at least 12 bytes; the next 32 are the NodeKey only if present and not all zero. Minimal ping packet 124 bytes. **Pong** payload: `TxID(12) | Src(16-byte IPv6-form IP, IPv4 as ::ffff:a.b.c.d) | port(BE16)`, at least 30 bytes; packet 110. Over DERP, the responder's Src is `127.3.3.40` with the port set to the region ID the ping arrived on; receivers ignore Src for DERP pongs.
3. **Answering over DERP.** Upstream drops a disco packet whose sender disco key is not a known peer's, or whose box does not open; over DERP it then requires the frame source to be a peer. It does not check the ping's NodeKey or that the header key is that peer's netmap disco key, and has no pong rate limit. It replies on the same region the ping arrived on, to the frame source, sealed to the header's disco key. (This plan is stricter: header key must equal the frame source peer's netmap disco key, plus rate limits.)
4. **`tailscale ping` CLI.** Flags `-c` (10; 0 = forever), `--timeout` (5s per ping), `--until-direct` (true), `--verbose`, `--tsmp`, `--icmp`, `--peerapi`, `--size`. Not running: prints the state, exit 1. Self IP: `<ip> is local Tailscale IP`, exit 0. Each iteration is one ping with its own timeout. Timeout: `ping "<ip>" timed out` (IP quoted); on the last iteration: error `no reply` if no pong ever, else exit 0; otherwise next iteration with no pause. Pong: `pong from <name> (<ip>) via DERP(<code>) in <latency>`, name = first label of the peer's DNS name; latency rounded to the millisecond and printed as Go `Duration.String()` (`0s`, `23ms`, `1.5s`); `<code>` is the region the ping was SENT to (the peer's home region). After a pong: if direct and until-direct, exit 0; then sleep 1 s; on the last iteration: until-direct → error `direct connection not established` (exit 1), else exit 0. Errors print and exit 1 (recalled). Error texts: `unknown peer`, `peer's node key has expired`.
5. **Peers' behaviour.** Our pings make peers answer only with pongs. Without advertised endpoints, peers send us no UDP pings and no CallMeMaybe; a CallMeMaybe, if one comes, is advisory and safe to ignore. A peer that does not yet know our disco key (from the netmap or the TSMP advertisement we already send) drops our ping silently.
6. **No capability gate** for disco ping/pong at capability version 150. Our MapRequest already sends `DiscoKey`.
