# Daemon and Install (milestone 7) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** tsppc installs from a standard Installer package, runs from launchd at boot with no login, survives sleep, network changes and crashes, and uninstalls without leaving routes or hosts entries, on Leopard and Tiger.

**Architecture:**
- **Detection.** Sleep is a gap between the wall clock and the monotonic clock across a loop turn. A network change is a change in a fingerprint of the interface addresses and the default route, polled every few seconds. Both are pure functions in `src/daemon/conditions.c`, fed by `src/platform/netinfo.c`.
- **Rebind.** Either event triggers one rate-limited rebind. Rebinding closes and reopens the control connection and every relay connection, and drops all WireGuard sessions. The tun device and its routes stay up, so connections on the tailnet address survive.
- **Packaging.** A hand-built bundle-style Installer package (Tiger cannot read flat packages) carries:
  - the two programs;
  - the renamed kext (its own bundle ID, so tsppc never unloads another tuntaposx);
  - a Tiger-safe LaunchDaemon plist;
  - the menu bar app;
  - an uninstaller.
- **Kext loading.** The daemon loads the kext itself when no tun device exists, so boot never waits on the driver.

**Tech Stack:** C (gnu99, gcc-4.0, 10.4u SDK for PowerPC; clang with ASan/UBSan on the host), Objective-C/Cocoa for the menu bar app, POSIX sh for the scripts, `pax`, `mkbom`, `hdiutil`, `launchctl`, `kextload`.

## Global Constraints

- Build flags: `gcc-4.0 -std=gnu99 -arch ppc -isysroot /Developer/SDKs/MacOSX10.4u.sdk -mmacosx-version-min=10.4`, `-Wall -Wextra -Werror`. Only APIs in the 10.4u SDK.
- Nothing may assume big-endian or 32-bit. The host suite (`make test`, `make asan`, `make fuzz`) and the PowerPC suite (`tools/vm-test.sh leopard|tiger`) both pass after every task.
- Every buffer has a compile-time limit. Logs and status never hold keys or the login URL.
- The LaunchDaemon plist uses only keys Tiger understands: `Label`, `ProgramArguments`, `RunAtLoad`, `OnDemand`. No `KeepAlive`.
- Install layout:
  - `/usr/local/sbin/tsppcd`, `/usr/local/bin/tsppc`, `/usr/local/sbin/tsppc-uninstall`;
  - `/Library/Extensions/tsppc-tun.kext`;

  - `/Applications/tsppc.app`;
  - log at `/var/log/tsppcd.log`;
  - state stays in `/var/db/tsppc`.
- Kext bundle ID `com.github.ajthom90.tsppc.tun`; package identifier `com.github.ajthom90.tsppc.pkg`.
- Never replace, load, unload or delete another tuntaposx install: `tun.kext` in `/Library/Extensions` or `/System/Library/Extensions`, or a loaded `foo.tun`.
- Anti-goal: never leave a Mac broken. No stale routes, no damaged `/etc/hosts`, no boot that hangs on the driver.

- Public repository: no usernames, hostnames, tailnet names, addresses, keys or login URLs in commits or records. Use placeholders.

## Review Focus

1. **A network that flaps** (DHCP renew, Wi-Fi reassociating, an interface going up and down every few seconds). Expected: at most one rebind per `TS_REBIND_MIN_GAP_MS`; a change during the gap is applied once when the gap ends; never a reconnect storm. Pinned in Task 1 (`rebind gate` tests).
2. **The wall clock stepped by the user or by NTP at boot**, forward or backward. Expected: one rebind, logged as a clock jump, nothing worse. Pinned in Task 1 (`wake: backward jump` test) and Task 3 (simulated wake).
3. **Uninstall after `kill -9`**, with the daemon not running and a route and names block left behind. Expected: the uninstaller still removes both. Pinned in Task 4 (`--cleanup` test) and Task 8 (live).
4. **Another tuntaposx already loaded.** Expected: tsppcd uses the existing `/dev/tunN` and never loads its own kext. The uninstaller leaves the foreign kext loaded. Pinned in Task 5 (kextload is skipped when a tun device opens) and Task 8 (live, with the VMs' development `foo.tun` loaded).
5. **An upgrade over a running daemon.** Expected: the old daemon stops before the files are replaced; the new one starts with the same identity and no login. Pinned in Task 6 (preflight) and Task 8 (live).

### Task 1: Wake, network fingerprint and rebind gate (pure core)

**Files:**
- Create: `src/daemon/conditions.h`, `src/daemon/conditions.c`, `src/platform/netinfo.h`, `src/platform/netinfo.c`, `tests/test_conditions.c`
- Modify: `Makefile` (new objects in the daemon and the test build), `tests/main.c` (register the suite)

**Interfaces:**
- Produces, in `src/daemon/conditions.h`:
  - `#define TS_WAKE_JUMP_MS 15000`, `#define TS_NET_POLL_MS 5000`, `#define TS_REBIND_MIN_GAP_MS 10000`
  - `typedef struct { int primed; int64_t wall, mono; } ts_wake;`
  - `int64_t ts_wake_check(ts_wake *w, int64_t wall_ms, int64_t mono_ms);` returns the jump: `(wall - wall0) - (mono - mono0)` in ms when its absolute value is at least `TS_WAKE_JUMP_MS`, else 0. The first call only primes it. Every call re-primes.
  - `typedef struct { char name[16]; uint32_t addr, mask; } ts_ifaddr;` (IPv4, host byte order)
  - `uint64_t ts_net_fingerprint(const ts_ifaddr *a, size_t n, uint32_t gw, const char *gw_if);`
    - Ignores entries whose name starts with `lo`, `tun`, `tap`, `utun` or `gif`, and addresses in 100.64.0.0/10.
    - Independent of entry order: sort a bounded copy, at most `TS_NET_MAX_ADDRS` = 32 entries; extras are ignored after sorting by name and address.
    - FNV-1a 64 over the result plus `gw` and `gw_if`.
  - `typedef struct { int64_t last; int pending; char why[64]; } ts_rebind_gate;`
  - `void ts_rebind_request(ts_rebind_gate *g, const char *why, int64_t now_ms);`
  - `int ts_rebind_due(ts_rebind_gate *g, int64_t now_ms, char why[64]);` returns 1 and fills `why` when a request is pending and either there was no earlier rebind or `now - last >= TS_REBIND_MIN_GAP_MS`. It then clears pending and sets `last = now`. If several requests are pending, the earliest `why` wins.
- Produces, in `src/platform/netinfo.h`: `int ts_net_snapshot(ts_ifaddr *out, size_t cap, size_t *n, uint32_t *gw, char gw_if[16]);`
  - Uses `getifaddrs` for interfaces that are `IFF_UP`, with `AF_INET` only.
  - Gets the default route with an `RTM_GET` for 0.0.0.0/0 on a `PF_ROUTE` socket. No default route gives `gw = 0` and `gw_if = ""`.
  - Returns 0, or -1 when `getifaddrs` fails.

### Task 2: Rebind in the WireGuard device, the data plane and its I/O

**Files:**
- Modify: `src/wg/device.h`, `src/wg/device.c`, `src/data/dataplane.h`, `src/data/dataplane.c`, `src/daemon/dataplane_io.h`, `src/daemon/dataplane_io.c`
- Test: `tests/test_wg_device.c`, `tests/test_dataplane.c`, `tests/test_dpio.c`

**Interfaces:**
- Produces: `void ts_wg_reset_sessions(ts_wg_dev *d);`
  - Wipes every peer's keypairs and any handshake in progress, and forgets queued handshake retries.
  - Keeps peers, AllowedIPs and statistics.
  - The next packet to a peer starts a new handshake.
- Produces: `void ts_dp_rebind(ts_dp *dp, int64_t now_ms);`
  - Every relay slot that is dialing or up is closed through `io->conn_close` and dialed again at the next `ts_dp_tick`, with its backoff reset to `TS_DP_REDIAL_MIN_MS` and no delay.
  - Calls `ts_wg_reset_sessions`.
  - Pending pings are left to finish or time out.
  - Does nothing if not running.
- Produces: `void ts_dpio_rebind(const char *why, int probe_again);`
  - Does nothing unless the data plane is running.
  - Logs `rebinding relays (<why>)`, calls `ts_dp_rebind`, and makes sure every relay socket is closed.
  - With `probe_again`, cancels running home probes and starts a new round on the next sync.
  - The tun device, its address and the route are untouched.

### Task 3: Daemon: sleep and network change trigger a rebind

**Files:**
- Modify: `src/daemon/main.c`
- Test: `tests/test_ipc.c` (end-to-end, with the fake control)

**Interfaces:**
- Consumes: Task 1 (`ts_wake_check`, `ts_net_snapshot`, `ts_net_fingerprint`, `ts_rebind_request`, `ts_rebind_due`) and Task 2 (`ts_dpio_rebind`).
- Behaviour in the main loop (each turn, after `ts_dpio_sync`):
  - **Wake.** Run `ts_wake_check` with the wall clock (`gettimeofday`, in ms) and `now_ms()`. A non-zero result logs `woke from sleep (wall clock jumped <n> s)` and requests a rebind with why `woke from sleep`.
  - **Network.** Every `TS_NET_POLL_MS`, take a snapshot and fingerprint it. The first one only primes. A different value logs `network changed` and requests a rebind with why `network changed`. A failed snapshot is ignored.
  - **Rebind** when `ts_rebind_due` is true:
    - If a control connection exists (any phase other than `C_NONE`), close it with `conn_close()` and call `ts_sess_disconnected(D.sess, why)`.
    - Call `ts_dpio_rebind(why, 1, reset)`. `reset` is 1 only when a forward wake (`ts_wake_check` > 0) was requested since the last rebind. Keep it in a flag beside the gate, set by a forward wake and cleared at each rebind. A backward jump and a network change pass 0 (see Amendments).
  - The session's own backoff decides the reconnect delay. After `TS_SESS_BACKOFF_RESET_MS` in RUNNING, that delay is at most 1 s.
  - **Test builds only** (`TS_TEST_HOOKS`): SIGUSR1 requests a rebind as a wake (logged `woke from sleep (test signal)`), and SIGUSR2 as a network change (logged `network changed (test signal)`). They go through the signal pipe; release builds do not install these handlers.
- The loop's longest sleep stays `LOOP_MS` (1 s), so a wake is noticed within a second.

### Task 4: Daemon log file, arguments and cleanup mode

**Files:**

- Modify: `src/daemon/main.c`, `Makefile`, `tests/main.c`, `tests/test_ipc.c`

**Interfaces:**
- Produces:
  - `#define TS_LOG_MAX (1024 * 1024)`
  - `int ts_logfile_open(const char *path, char *err, size_t cap);`
    - Opens `O_WRONLY|O_APPEND|O_CREAT|O_NOFOLLOW`, mode 0644.
    - Refuses anything that is not a regular file.
    - `dup2`s it onto `STDERR_FILENO`. Returns 0 or -1.
  - `void ts_logfile_check(void);`
    - When a file is open and `fstat` shows a size ≥ `TS_LOG_MAX`, renames it to `<path>.1` (replacing any old one) and opens a new file the same way.
    - Does nothing when no file is open.
- Command line: `tsppcd` (foreground, stderr, as now), `tsppcd -l <path>`, `tsppcd --cleanup`. Anything else prints the usage line and exits 2.
  - `-l`: the daemon calls `ts_logfile_check()` after each log line.
  - `--cleanup`: if a daemon answers on the control socket, print `tsppcd is running; stop it first` and exit 1. Otherwise run `ts_dpio_cleanup_route()` and `ts_names_cleanup()` (with their usual logging to stderr) and exit 0. It never loads state, keys or the network.

  - `ProgramArguments` = `/usr/local/sbin/tsppcd`, `-l`, `/var/log/tsppcd.log`;

  - `OnDemand` = false.
- **`tools/package.sh <version>`** runs on the Leopard VM from a tree where `make release ppc`, `make menubar` and `tools/driver.sh build` have run.
  - Fails if `<version>` differs from `TS_IPN_VERSION` without its `-ppc` suffix.
  - Stages a root tree, using `sudo` to set root:wheel ownership (the app root:admin, mode 0775 directories):
    - binaries 0755;
    - the uninstaller 0755;
    - the plist 0644;
    - the kext directories 0755 and files 0644.
  - Builds a **bundle-style** `build/release/tsppc-<version>.pkg`:
    - `Contents/Archive.pax.gz` (`pax -w -x cpio -z` from the staging root);
    - `Contents/Archive.bom` (`mkbom`);
    - `Contents/Info.plist`, from `Info.plist.in`:
      - `CFBundleIdentifier com.github.ajthom90.tsppc.pkg`;
      - `CFBundleShortVersionString <version>`;
      - `IFPkgFlagAuthorizationAction RootAuthorization`;
      - `IFPkgFlagDefaultLocation /`;
      - `IFPkgFlagRelocatable false`;
      - `IFPkgFlagRestartAction None`;
      - `IFPkgFlagRootVolumeOnly true`;
      - `IFPkgFormatVersion 0.1`;
    - `Contents/PkgInfo` (`pmkrpkg1`);
    - `Contents/Resources/` with `preflight`, `postflight`, `ReadMe.txt` and `License.txt`. `License.txt` is the repository `LICENSE` plus the tuntaposx and BearSSL notices.
  - Then builds `build/release/tsppc-<version>.dmg` (UDZO, readable on Tiger) holding the package, `tsppc-uninstall` and `ReadMe.txt`.
  - Ends by running `tools/check-pkg.sh` on the package.
- **`ReadMe.txt`** opens with: `tsppc is an unofficial Tailscale client for PowerPC Macs. It is not affiliated with or endorsed by Tailscale Inc.` It then says what is installed where, that the daemon starts at boot, and how to uninstall (`sudo /usr/local/sbin/tsppc-uninstall`).
- **preflight** (runs as root):
  - If `/Library/LaunchDaemons/com.github.ajthom90.tsppcd.plist` exists, `launchctl unload` it.
  - Then wait up to 30 s, using `ps ax`, for no `tsppcd` process to remain. Do not use `ps -p`, which succeeds for a gone pid on Tiger. Fail the install if one remains.
  - Refuse a target other than `/`.
- **postflight:**
  - `launchctl load -w` the plist.
  - Unless `COMMAND_LINE_INSTALL` is set, and when `/dev/console` is owned by a user other than root, open `/Applications/tsppc.app` as that user (`sudo -u <user> /usr/bin/open`). Failure there is not fatal.
  - Exit 0.
- **`tools/uninstall.sh`** (installed as `/usr/local/sbin/tsppc-uninstall`):
  - Must run as root. Asks `Remove tsppc? [y/N]` unless given `-y`. `--remove-state` also deletes `/var/db/tsppc`, after a second confirmation saying the node stays in the tailnet's admin console until removed there.
  - Steps:
    1. `launchctl unload` the plist and wait for `tsppcd` to exit (as in preflight). If none is running, go on.
    2. Run `/usr/local/sbin/tsppcd --cleanup`.
    3. Quit `/Applications/tsppc.app` (SIGTERM the processes whose command path is the app's executable).

## Amendments

- **Task 2, session reset only for a real sleep (controller ruling).**
  - The signatures are now `ts_dp_rebind(ts_dp *dp, int64_t now_ms, int reset_sessions)` and `ts_dpio_rebind(const char *why, int probe_again, int reset_sessions)`.
  - WireGuard sessions are reset, and queued WireGuard messages dropped, only for a forward wall-clock jump.
  - A backward jump and a network change redial the relays and reconnect control, but keep the sessions. A backward step would make peers refuse new initiations (TAI64N comes from the wall clock), and the spec asks for session teardown only on sleep and wake.
- **Note for milestone 14 (self-update).** The package's preflight unloads the running daemon. A daemon that runs `/usr/sbin/installer` itself must start it as a detached child (its own session, not in the launchd job's process group), or unloading the job kills the installer partway.
