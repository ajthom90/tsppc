# Services (milestone 5) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Peers' names resolve on the Mac through a tsppc block in `/etc/hosts`, and SSH (both directions) and an AFP mount work over the tunnel between the two VMs.

**Architecture:** A sans-I/O module (`src/names/hosts.c`) builds the block from the network map and merges it into the old file's text. A small platform file (`src/platform/hostsfile.c`) reads and atomically replaces `/etc/hosts` and flushes the resolver cache. The daemon (`src/daemon/names_io.c`) decides when to write and remove. The milestone's acceptance is a live check recorded in `docs/services-check.md`.

**Tech Stack:** C99 (gnu99), gcc-4.0 with the 10.4u SDK for PowerPC, clang with ASan/UBSan and the in-tree fuzz harness on the host.

**Spec:** `docs/superpowers/specs/2026-11-10-tailscale-ppc-design.md`: "Names (what 'MagicDNS basics' means)", milestone 5, "Known limits", "Leaving a Mac broken" anti-goal.

## Global Constraints

- Same build flags as the rest: `-std=gnu99 -Wall -Wextra -Werror`, gcc-4.0 for `ppc` against the 10.4u SDK, and the host build with clang. `make test`, `make asan`, `make fuzz` and `tools/vm-test.sh leopard` must pass.
- Every parser of untrusted input (here: names from control, and the existing hosts file) has unit tests, runs under ASan and UBSan, and gets a fuzz target in `tests/fuzz_*.c`.
- No Mac dependency in `src/names/`. Platform code only in `src/platform/` and `src/daemon/`.
- Test-only behaviour goes behind `TS_TEST_HOOKS`, and `tools/check-release.sh` must keep proving release binaries have none (add any new hook symbol or environment variable name to its list).
- The repository is public: no hostnames, usernames, tailnet names or IPs of real machines in code, tests or docs. Records use placeholders such as `<leopard>`.
- Respect `NodeAttrDisableHostsFileUpdates`: the capability string is `disable-hosts-file-updates` (tailscale `tailcfg/nodecap`, capver 132 "client respects" it; we advertise 150).
- Never leave a Mac broken: every line of the hosts file outside the tsppc block survives byte for byte, the block is gone after `down`, logout, a clean stop, and the next start after a crash.

## Review Focus

1. A peer name from control containing a newline, `#`, a space or other bytes must never reach `/etc/hosts` (injection of arbitrary host entries). Covered by Task 2's validation tests and fuzz target.
2. A hosts file with a begin marker and no end marker (hand-edited, or a crash mid-write of some other tool) must not lose the owner's lines that follow. Task 2 refuses to touch it.
3. Two peers with the same short name (shared-in nodes from another tailnet): neither gets the short name; the full names still resolve. Task 2.
4. A hosts file that is a symlink or not a regular file, or is over the size limit: left alone, and `status` says why. Task 3.
5. An unchanged map must not rewrite the file (the map sends keep-alives and online changes all the time). Task 3 compares with the last written block.

### Task 2: The hosts block, sans I/O

**Files:**
- Create: `src/names/hosts.h`, `src/names/hosts.c`
- Create: `tests/test_hosts.c`, `tests/fuzz_hosts.c`
- Modify: `Makefile` (new sources in both host and ppc builds), `tests/main.c`

**Interfaces:**
- Consumes: `ts_netmap` (`self`, `have_self`, `peers`, `npeers`; `ts_node.name`, `ipv4`, `have_ipv4`).
- Produces:
  - `#define TS_HOSTS_BEGIN "# tsppc begin: peer names from your tailnet, rewritten by tsppcd"`
  - `#define TS_HOSTS_END "# tsppc end"`
  - `#define TS_HOSTS_FILE_MAX 1048576` (larger existing file: refuse)
  - `#define TS_HOSTS_BLOCK_MAX` sized for `TS_MAX_PEERS + 1` entries at the longest line, plus markers.
  - `int ts_hosts_name_ok(const char *name, char *fqdn, size_t fqdn_cap, char *shortname, size_t short_cap);` Validates a node `Name` from control: optional single trailing dot removed; 1..253 bytes; dot-separated labels of 1..63 bytes from `[A-Za-z0-9-]`, not starting or ending with `-`; at least one label. Writes the name without the trailing dot, lowercased, and its first label. Returns 0 if valid, -1 otherwise (nothing reaches the file).
  - `int ts_hosts_build(char *out, size_t cap, const ts_netmap *nm, size_t *nentries, size_t *nskipped);` Writes the whole block: begin marker line, one line per node (self included) with an IPv4 address and a valid name, `"<a.b.c.d>\t<fqdn> <short>\n"` (just `"<a.b.c.d>\t<fqdn>\n"` when the short name is withheld), end marker line. Lines sorted by IPv4 ascending, then fqdn, so the same map always gives the same bytes. A short name used by more than one node is withheld from all of them; a short name equal to some node's fqdn is withheld too. Returns the length, or -1 if `cap` is too small. `nskipped` counts nodes with an address and an invalid name.
  - `int ts_hosts_merge(char *out, size_t cap, const char *old, size_t oldlen, const char *block, size_t blocklen);` Copies `old` with every tsppc section removed (from a line equal to `TS_HOSTS_BEGIN` through the next line equal to `TS_HOSTS_END`, both inclusive; a line matches after trailing spaces, tabs and `\r` are ignored; a lone `TS_HOSTS_END` line is removed too). Every other byte is kept, including a missing final newline, NUL bytes and CRLF endings. If `blocklen > 0`, appends the block, first adding `\n` if the kept text is non-empty and does not end in one. Returns the length; `-1` if `cap` is too small or `oldlen > TS_HOSTS_FILE_MAX`; `-2` if a begin marker has no end marker after it (the caller must not write).

- [ ] **Step 1:** Tests for `ts_hosts_name_ok` (valid FQDN with and without trailing dot; uppercase lowered; empty, `.`, `..`, 254 bytes, 64-byte label, `a\nb`, `a b`, `a#b`, `a_b`, `-a`, `a-.b`, a NUL in the middle via a fixed array) and `ts_hosts_build` (self plus peers sorted by IP; a peer without IPv4 left out; an invalid name counted in `nskipped`; duplicate short names withheld from both; same map twice gives identical bytes; too-small `cap` returns -1).
- [ ] **Step 2:** Tests for `ts_hosts_merge`: empty old; old without a block keeps every byte and adds `\n` only when missing; old with a block in the middle replaces it and keeps lines before and after; two blocks both removed; markers with `\r\n` and trailing spaces matched; begin without end returns -2; lone end line removed; `blocklen == 0` removes the block and adds nothing; NUL bytes in other lines survive; `oldlen > TS_HOSTS_FILE_MAX` returns -1.
- [ ] **Step 3:** Run `make test`; the new tests fail (or do not build).
- [ ] **Step 4:** Implement.
- [ ] **Step 5:** `tests/fuzz_hosts.c`: feed arbitrary bytes as `old` and as a node name; check `merge` never writes past `cap`, its output never contains `TS_HOSTS_BEGIN` except the appended block's, and a valid name output contains only `[a-z0-9.-]`.
- [ ] **Step 6:** `make test`, `make asan` and `make fuzz` pass. Commit.

### Task 3: Writing `/etc/hosts` from the daemon

**Files:**
- Create: `src/platform/hostsfile.h`, `src/platform/hostsfile.c`, `src/daemon/names_io.h`, `src/daemon/names_io.c`
- Create: `tests/test_names_io.c`
- Modify: `src/daemon/main.c`, `src/cli/main.c`, `Makefile`, `tests/main.c`, `tools/check-release.sh`

**Interfaces:**
- Consumes: Task 1's `no_hosts_file`, Task 2's functions, `ts_sess_netmap`, `ts_dpio_get_view` (`running`), `ts_run` from `src/platform/tun.h`.
- Produces:
  - `src/platform/hostsfile.h`:
    - `int ts_hostsfile_read(const char *path, char *buf, size_t cap, size_t *len, char *err, size_t errcap);` `lstat` first: not a regular file means -1 with "not a regular file"; missing file means 0 with `*len = 0`; larger than `TS_HOSTS_FILE_MAX` means -1 with "too large".
    - `int ts_hostsfile_write(const char *path, const char *buf, size_t len, char *err, size_t errcap);` Temp file `<dir>/.hosts.tsppc.XXXXXX` by `mkstemp` in the same directory, write all, `fchmod` and `fchown` to the existing file's mode and owner (0644 root:wheel when it did not exist), `fsync`, `rename` over `path`. On any failure the temp file is unlinked and the original is untouched.
    - `void ts_hostsfile_flush_cache(void);` Runs `/usr/bin/dscacheutil -flushcache` if it is executable (10.5), else `/usr/sbin/lookupd -flushcache` if executable (10.4), through `ts_run`. Ignores the result.
  - `src/daemon/names_io.h`:
    - `void ts_names_init(ts_dpio_log_fn logf);`
    - `void ts_names_cleanup(void);` At start (after the listen check, beside `ts_dpio_cleanup_route`) and from `ts_names_shutdown`: removes a tsppc block if there is one, and flushes the cache only if it removed one.
    - `void ts_names_sync(const ts_netmap *nm, int running, int map_changed, int64_t now_ms);` After `ts_dpio_sync` each loop turn, with `nm` from `ts_sess_netmap` (NULL when no session). While `running` and `nm->have_self` and not `nm->self.no_hosts_file`: when `map_changed` (or the last write failed), build the block; write only if the block differs from the last one written, and at most once every `TS_NAMES_MIN_GAP_MS` (5000), keeping a pending flag so the last change is always written. When not running, or the capability is set: remove the block once. A failed write is retried after `TS_NAMES_RETRY_MS` (30000). Flush the cache after each successful change.
    - `void ts_names_shutdown(void);` Removes the block (SIGTERM, SIGINT, normal exit).
    - Status: `void ts_names_status(char *out, size_t cap);` one of `off` (not running), `disabled by tailnet`, `<n> names` (with `, <m> skipped` when some were invalid), `hosts file: <reason>` (read or write failure, broken section, not a regular file, too large).
  - Status key `names` added by `build_status` in `src/daemon/main.c`; the CLI prints `names: <value>` after `filter:` (extend `scan_extras`).
  - Test builds: `TSPPC_HOSTS_FILE=<path>` replaces `/etc/hosts`, and `TSPPC_NO_TUN=1` also skips the cache flush. Add both to `tools/check-release.sh`'s hook list.

## Amendments

Changes made while implementing and reviewing, which the tasks above predate:

- `ts_hosts_build` takes the old file's text (and later this Mac's short host name), so short names never shadow the owner's own entries or the Mac's own name.
- Security hardening of the block: short names only for nodes with self's exact suffix, reserved names (`localhost`, `wpad`, ...) never written as short names, duplicates withheld.
- The "block differs from the last one written" compare is replaced by "merged text equals the file": no write when nothing changes, and a block deleted by hand comes back at the next map change.
- Full names are gated too: a node is written only if its name ends in self's suffix or in `ts.net` (label boundary); others are skipped and counted.
- Names are written only while the tunnel is open (data plane running and tun device open), not just while the data plane runs.
- `ts_netmap.nodes_gen` (bumped when self or the peers change): with the same `nodes_gen`, host name and hosts file (dev, inode, size, mtime, ctime), the daemon skips the read, build and merge entirely.
